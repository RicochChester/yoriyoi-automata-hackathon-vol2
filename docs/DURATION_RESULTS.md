# 会話機会を増やすとBridgeは回復するか

2026-09-11実行。**形成数の差は縮小したが、48ターンでも解消していない。**

本モデルでは、会話機会を増やすとBのBridge形成数が増え、Aとの平均差は縮小した。一方、既知相手への会話集中と、第三者との形成の遅れは残った。「十分な時間ならトレードオフが解消する」とまでは言えない。

## 実験条件と正本

対象はローカルのYoriyoi提出ソースを基にした作業コピー。取得元は RicochChester/yoriyoi-automata-hackathon-vol2、取得revisionは `1cc02b28f850b2843c464f91146fd6b89c34f9a9`。Gitの追跡済みファイルがないため、実験時点の正本はソースのSHA-256と全設定を記録した `results/duration-101-1100/design.json` と `manifest.json` で固定した。

4人、ルール版、Bの既知ペアは「あかね―みどり」で固定。12・24・36・48ターン、それぞれseed 101〜1100、A/B各1回。計4,000組・8,000条件実行。前回と同じseedであり、独立した新規1000 seedによる追試ではない。

比較対象は既知ペアの両端から第三者へ伸びる共通4ペア。「顔見知り」または「親しみがある」を成立と数える。A/Bとも分母4。元の選択、反応、関係判定、性格、オンライン関係の各作用は変更していない。

実行前に [計画](DURATION_PLAN.md) を保存した。短い実行と長い実行の先頭部分が一致することを全seedで確認したため、別の世界を引き直す比較ではなく、同じ世界を長く観察する比較になっている。

## 主結果

| ターン数 | A 平均Bridge数 /4 | B 平均Bridge数 /4 | B−A | 差の95%区間 |
|---:|---:|---:|---:|---:|
|12|2.342|2.098|−0.244|[−0.276, −0.212]|
|24|3.062|2.901|−0.161|[−0.187, −0.135]|
|36|3.363|3.242|−0.121|[−0.145, −0.097]|
|48|3.530|3.438|−0.092|[−0.114, −0.070]|

Bの形成数は2.098から3.438へ増えた。差の絶対値は約62.3%縮小した。あらかじめ主対比とした「48ターンのB−A」から「12ターンのB−A」を引いた値は **+0.152件、95%区間 [+0.116, +0.188]**。これはseedごとの対応を保って計算している。

48ターンでも率はA 88.25%、B 85.95%で、Bが2.30ポイント低い。1000 seed中、Bが多い15、同数882、Bが少ない103。同数が多いことと、平均差がゼロであることは別である。

区間は1000個のseed内差の標本平均 ± 1.96×標準誤差による大標本近似。ペア4本や同一seedの4時点を独立標本として水増ししていない。各時点の区間は点ごとの区間で、同時区間ではない。これはモデルの乱数による変動を表し、人間や別モデルへの不確実性を包含しない。平均の標準誤差に基づく区間の考え方は [NISTの解説](https://www.itl.nist.gov/div898/handbook/eda/section3/eda352.htm) を参照した。等価性の許容幅は未設定で、「効果が解消した」という判定はしていない。

## なぜ「初期集中が消えた」とは言えないか

既知ペア内の会話回数を、全会話回数で割った割合は次のとおり。Aについても同じ「あかね―みどり」を数えた。

|ターン数|A 既知ペア相当への会話割合|B 既知ペアへの会話割合|A 全Bridge成立のseed割合|B 全Bridge成立のseed割合|
|---:|---:|---:|---:|---:|
|12|12.52%|19.78%|3.0%|0.7%|
|24|12.73%|19.85%|24.5%|16.1%|
|36|12.83%|19.59%|42.4%|34.1%|
|48|12.93%|19.43%|54.8%|48.1%|

Bの既知者への選好は長い実行でも持続した。追加の機会によって形成数が追いつく方向に動いたのであり、会話集中そのものがなくなったわけではない。

また、Bridge数には4本という上限があり、このモデルの成立済みの関係は後退しない。長く観察すると両条件が上限に近づくため、差の縮小には天井への接近も関わり得る。この実験だけでは、縮小をすべて「初期の影響が解消した」と説明できない。

## 形成までの遅れ

最終状態に加え、各ターン終了時にまだ未形成だった回数を、4本のBridgeについて平均した。初めて成立したターンがτならτ−1、最後まで未形成なら観察したターン数を記録する。未成立ペアも残し、成立ペアだけを選んで平均する偏りを避けた。

48ターンの観察範囲では、この累積未形成回数はA **15.873**、B **17.643**。B−Aは **+1.771ターン相当 / Bridge、95%区間 [+1.575, +1.966]** だった。最終形成数が近づいても、形成までの遅れの累積は残る。

これは48ターンを上限とする指標であり、全員の完全な形成待ち時間の平均でも、実時間の分数でもない。未成立ペアのその後は不明（打ち切り）。観察上限が異なる指標同士の大小だけで遅れの悪化を判断しない。

## 変更前 → 変更後

新規の `poc/ab_poc/duration_experiment.py` が実験を担当する。既存の `engine.py` は会話を進め、`config.py` は通常の12ターン設定を読む。この2ファイルを編集する必要はなかった。

変更前は読み込んだ12ターン設定で実行する。

```python
config = load_config()
result = run_ab(seed=seed, config=config)
```

変更後は設定をコピーし、ターン数だけを置き換えて同じエンジンへ渡す。

```python
config = load_config()
config = replace(config, rules=replace(config.rules, turns=turns))
result = run_ab(seed=seed, config=config)
```

新規モジュールの `duration_config` がこのコピーを担当し、`run_study` が全条件を実行する。`extract` が初成立時点と会話配分を取り出し、`summarize` がseed内差を集計する。既存の共通ペア分類・保存処理・区間計算を再利用した。

追加した `tests/test_duration_experiment.py` は設定差、先頭一致、打ち切り、集計、保存と上書き防止を確認する。`validation/verify_duration.py` は保存された会話から全時点の関係を作り直し、CSVと照合する。通常UIは引き続き12ターンで動く。

## 検証と制約

- 29テスト成功。共有検証環境のpytestでも29テストと8 subtests成功。
- 実際のCLIから8,000条件を完走。短い実行との先頭一致6,000件。
- 48,000ペア行、全時点の関係、初成立時点、未形成回数を保存済み会話から再構成して一致。
- 前回の12ターン・同じ1000 seedの会話、最終関係、指標、ルールが一致。
- 元の43個のpocファイルはバイト単位で同一。前の100 seed成果物も再検証成功。
- Pythonコンパイル確認成功。外部API、追加パッケージ、課金は使用していない。

証拠は `validation/duration-audit.json`、`duration-tests.txt`、`duration-engineering-closeout.json`、`artifact-audit.json` にある。統合closeoutはGit追跡ファイル未登録と公開向け個人パス検査などで **blocked**。これは公開準備の未完了であり、上記のローカル実験検証とは区別する。Git設定の変更・push・公開は行っていない。先行実装調査用の依存スキル不足による研究ゲートのholdも、解消済みとはしていない。

モデル内部の結果であって、実際の交流会や別の人物組み合わせに対する保証ではない。ABMでは乱数による変動の評価と条件感度の分析を区別する必要があり、今回は人物固定で会話機会だけを変えた分析である。[LeeらのABM出力分析](https://www.jasss.org/18/4/4.html) も参照した。

## 自分で再実行する手順

PowerShellで、まずプロジェクトへ移動する。

```powershell
Set-Location "<cloneしたリポジトリのフォルダ>"
```

少量で動作を確かめる。

```powershell
.\.venv\Scripts\python.exe -X utf8 -m poc.ab_poc.duration_experiment --seed-start 101 --seed-end 103
```

1000 seedを再実行する。

```powershell
.\.venv\Scripts\python.exe -X utf8 -m poc.ab_poc.duration_experiment
```

出力先を指定しなければ時刻付きの新しいフォルダができ、今回の結果は上書きしない。処理終了時に保存先が表示される。専用venvがない別環境ではPython 3.10以上の `python` を使える。今回はWindows・Python 3.12.14で確認した。

今回保存済みの本実験を再検証する。

```powershell
.\.venv\Scripts\python.exe -X utf8 validation/verify_duration.py
```

途中でエラーになった場合、そのフォルダは完了成果物として使わず、表示されたエラー文と `manifest.json` の有無を確認する。既存フォルダへの上書きは拒否するため、新しい出力先でやり直す。元に戻すには追加実験コマンドの利用を止めればよく、元のモデルの復元は不要。ローカルコードと結果の保管は本プロジェクトで行う。

## 次の段階

|段階|今回の到達点|
|---|---|
|① 会話機会を増やすとBridgeは回復するか|完了。Bの形成数は増加しA/B差は縮小。ただし差と遅れが残存|
|既知ペアの人物を変える|未実施。既知関係一般への拡張には必要|
|② 何が滞在時間を延ばすか|未実施。現モデルには自発的な滞在・離脱の決定がない|
|③ 滞在を延ばす施策がBridgeも増やすか|未実施。②の検証と、同時間での施策比較が必要|

ターン数は外から与えた会話機会であり、本人が長く滞在することを選んだ結果ではない。したがって、共同作業・話題提供・シャッフルが滞在を延ばすことは今回測れていない。

次に②へ進む際は、まず滞在・離脱の仕組みと、その根拠にする観察データを決める。「施策を入れると長く滞在する」と設定するだけでは仮説をルールに書き込むことになる。根拠が未取得なら感度分析として扱い、現実の効果と呼ばない。

③では施策あり／なしと固定会話機会／滞在に応じた会話機会を分け、同じ時間でも会話配分が変わる直接の効果と、機会が増える効果を切り分ける。48ターンで差がなくなることは前提にしない。今回の一連の結果を「既知者一般」の結論にする前には、全6通りの既知ペアでの確認も残る。
