# 課題習熟度と分散情報：仕組みと操作

## 変更する場所と、その理由

既存の会話エンジン、人物、興味、慎重さ、反応点、関係閾値は変更していない。
追加はpoc/ab_poc/task_information_experiment.py、poc/config/task_information_v1.json、
tests/test_task_information_experiment.py、validation/verify_task_information.py、および本説明・実行前計画・報告書。

|処理|変更前|追加した処理|
|---|---|---|
|課題情報|役割の文言のみ|InformationStateが各人の持つ4種類の情報を保持|
|習熟度|なし|他者の3情報をどれだけ取得したかを0〜1で記録|
|話題|既存の興味・記憶・過去話題から選択|作業中に不足情報があれば、その情報について質問|
|情報取得|なし|返答で相手の持つ不足情報を1つ受け取る|
|接触|作業時の指定と通常の相手選択|保存済み通常共同作業の全48接触を再生|
|関係形成|既存評価器|同じ評価器。習熟度や情報数は入力しない|

新しい反応ボーナスはない。質問の話題が相手の興味と一致するかなどを、
既存のRuleResponseProviderが判定する。課題の質問でも好意的な反応になる保証はない。

## 情報と習熟度

4つの情報は「地域」「展示」「ものづくり」「食」に関する課題手順とする。
全員が同じ課題を行うが、この題材選択自体が実験仮定である。
通常条件では全員が4情報を既知。初めて条件では各人に1つだけをseedで割り当てる。
同じseedではA/B、強度を通じ所有者は同じ。人物の興味や既知ペアを割当判断に使わない。

初めて条件の習熟度は0。1つの自分の手がかりだけでは全体の進め方を知らないと解釈する。
他の情報を取得するごとに1/3ずつ増え、4つ揃うと1。進行度は4人の習熟度平均。
全員が4つ揃ったら課題完了として記録する。実際の成果物や技能を評価する指標ではない。
通常条件の進行度1は「必要情報が揃っている」の意味で、48ターン分の作業を既に実行した意味ではない。

誰が何を知っているかの目録を参照できると仮定し、話し手は相手の持つ不足情報を優先。
複数あるときは情報ID順。相手が持っていない場合にも質問するが取得はない。
返答で1情報だけを受け取り、会話は追加しない。聞き手への逆方向伝達はこの1会話では行わない。
情報は作業ブロックをまたいで保持し、取得した情報を他者に渡すこともできる。
反応が中立・かみ合わない場合でも、知っている情報自体は渡せる設定にする。
これは知識共有と社会的な反応を分離する仮定であり、結果とともに再検討できる。

## 同じ接触数を保証する方法

通常/初めての比較では48ターンすべての話し手・相手・順序が一致する。
Aは従来の共同作業A、Bは従来の共同作業Bを再生するので、A/B間の自然な接触差は従来どおり残す。
作業ブロックは48ターン版の弱6・中12・強24を使用し、全6ペアが各1・2・4回出現する。
非作業時には情報を交換しないが、作業中の話題と反応がその後の会話内容へ波及することはある。

話題候補の数が変わると乱数の消費数も変わり得る。そこで実際の話題選択には乱数のコピーを使い、
反応用の乱数位置は元の共同作業の話題選択に揃える。これにより、質問が増えただけで
反応用の偶然の値までずれることを防ぐ。通常条件の全会話・全状態一致を全件で検証する。

## 読み取れること・読み取れないこと

測るのは「情報の必要性→質問の話題→既存の反応→Bridge」の経路。
習熟度と情報配置を同時に変えているため、新奇性だけの効果を分離したものではない。
情報の必要性を既存の話題・興味ルールで表現したモデルであり、
人間の助け合いへの感謝、共同達成感、課題成功による喜びは入っていない。
接触を固定したため、相談のために会話回数・相手選択そのものが増える効果も対象外。

報告する主指標はBridge4本の成立数/4と件数。Bの初めて−通常を先に示し、A、B−A、差の差も示す。
形成の遅れ、全4本成立率、会話割合、質問数、情報取得数、進行度・完了率を併記する。
率の差は件数差/4。区間は同seed差に基づく正規近似95% Monte Carlo区間。
全6ペア平均はseed内で平均してから1000seedで集計する。題材やモデル選択の不確実性は含まない。

## 実行方法

リポジトリのフォルダでPowerShellを開き、少数seedで試す。

```powershell
.\.venv\Scripts\python.exe -X utf8 -m poc.ab_poc.task_information_experiment --seed-end 102
```

全1000seedを実行する。

```powershell
.\.venv\Scripts\python.exe -X utf8 -m poc.ab_poc.task_information_experiment
```

表示された出力フォルダを監査する。

```powershell
.\.venv\Scripts\python.exe -X utf8 validation/verify_task_information.py "results/表示されたフォルダ名"
```

出力は新規フォルダのみ。既存フォルダは上書きしない。APIキー不要、追加ライブラリ不要。
results/event-formats-48-101-1100の元記録を入力として使い、ハッシュを確認する。
これがない場合は元の48ターン共同作業記録の復元が必要。

各既知ペア下に全会話・全状態・情報移動のtraces.jsonl.gz、全ペアのpairs.csv、seed_metrics.csv。
上位のsummary.csv/jsonに主副指標、対応差、区間。design.jsonに設定とソースハッシュ。
manifest.jsonが本体完了、validation内の該当出力名-audit.jsonが保存記録の監査成功を示す。

失敗時は末尾の例外と最後のpair/seed進捗を確認する。自動再開・上書きはせず、原因確認後に新規出力先で再実行する。
従来コマンドを使用すれば今回の拡張は無効で、削除や元コードの巻き戻しは不要。
