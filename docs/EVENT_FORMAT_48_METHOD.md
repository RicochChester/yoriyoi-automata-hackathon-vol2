# 48ターン版：変更内容と実行手順

## 何を変えたか

既存の1ターンは1人から1人への会話、相手の返答、関係評価である。
48ターンでは予定話し手の4人順を12回繰り返す。イベント介入時だけ
話し手変更を許すという既存の承認済み機能を引き続き使用した。
通常ターンは予定話し手に戻す。2組同時会話は追加していない。

|場所|変更前 → 変更後|理由|
|---|---|---|
|poc/ab_poc/event_format_experiment.py|24ターン・9条件固定 → 設定を受け取る共通処理、既定値は旧版|旧実験を維持して重複実装を避ける|
|同ファイル contact_plan|2巡の方向反転 → 4巡でも交互に反転|強条件24接触を全6ペア各4回にする|
|同ファイル extract_event|打切り24、会話割合の分母24 → 設定されたターン数|48ターンの遅れと割合を正しく計算する|
|同ファイル summarize_event|9条件の対比 → 条件数に応じた対比・補正区間|中条件を含む13条件を集計する|
|poc/ab_poc/event_format_48_experiment.py（新規）|48ターン版の実行入口|従来コマンドとの取り違えを防ぐ|
|poc/config/event_formats_v2.json（新規）|介入配置・共同作業ブロック・版番号|実験条件をコードから分離し固定する|
|tests/test_event_format_48_experiment.py（新規）|指定位置・均等性・旧版一致などを検証|従来結果と新仕様を両方保護する|
|validation/verify_event_formats.py|24/48両対応、人物設定照合|全記録・関係状態・既存自由交流を監査する|
|validation/summarize_event_48.py（新規）|副指標の対応差・共同作業対比・日本語表|A/B双方の改善や形成時期を区別する|

今回はengine.py、rule_providers.py、元の人物設定、関係形成閾値を変更していない。
旧24ターン版の試験記録108 A/B実行との完全一致も確認した。
24ターン版の既存保存結果とmanifestは歴史的記録として保持する。
共通実験ファイルを拡張したため、過去manifestのソースハッシュと
現在ソースが一致しないこと自体は不具合ではない。

## 13条件

自由交流1条件、残る4形式それぞれ弱・中・強。配置は
EVENT_FORMAT_48_PLAN.mdおよびevent_formats_v2.jsonを参照する。

- 自由交流：元のルール版をそのまま48ターン実行。
- シャッフル：全6無向ペアを均等に1・2・4巡。seedごとに順序を決める。
- 共同作業：同じペア列を6ターン連続の作業ブロックに割り当てる。
- 紹介：全6ペア中、会話回数最少のペアを紹介。対象相手の選択重みへ1.0をそのターンだけ加える。会話相手を強制しない。
- 共通話題：そのターンの共有興味判定を全ペアで真にする。元の興味リスト、オンライン話題記憶の優先、個人興味と話題の一致判定は維持する。

紹介bonusは弱・中・強で同じ1.0。直前の相手を繰り返す場合は
既存の繰返し倍率を適用する。初期世界・予定話し手順・乱数方式はA/B共通。
ただし会話履歴が変わると、紹介先やその後の自然な会話も変わり得る。

## 共同作業とシャッフルは何が違うか

共同作業は、課題を進めるために必要な相手との会話を強制接触として表現する。
役割は「情報を渡す」「作業結果を確認する」「次の工程へつなぐ」を順に記録。
実際の作業成果・成功失敗・能力・新奇性・心理効果は実装しない。

今回は、これに加えて**共同作業は連続、シャッフルは分散**という配置の差がある。
ペア列・方向・回数は同じでも、通常会話を挟む位置と履歴が変わり、
話し手に回る機会も変わる。その差を測る。関係への直接加点はない。
両形式を同じ配置にした検証では、関係状態が一致する。

共同作業の初成立数は開始前・作業中・ブロック間・最終作業後を分ける。
最終作業後の観察は弱21、中7、強2ターンなので単純な件数比較は避ける。
全48ターンの未成立累積ターンも合わせて判断する。

## 保存するもの

results/event-formats-48-101-1100 内：

- design.json：48ターン設定、全6既知ペアの全人物設定・ルール、実行前ソースハッシュ。
- manifest.json：全件完了、実行数、開始終了時刻、入力・出力ハッシュ。
- summary.csv/json：6既知ペア×13条件、平均・通常95%区間・対比の同時区間。
- pooled.csv/json：seedごとに6ペアを等重みで平均した全体集計。
- 各既知ペア下のtraces.jsonl.gz：全会話、全関係状態、介入先、予定/実話し手、共通話題上書きなど。
- pairs.csv：全6ペアの最終関係、分類、初成立ターン、未成立の打切り。
- seed_metrics.csv：全主・副・補助指標と人物別発話回数。

results/event-formats-48-analysis-101-1100 内：

- secondary_contrasts.csv/json：各副指標でもB−自由B、A−自由A、B−A、差の差を同seedで比較。
- task_vs_shuffle.csv/json：同接触回数での連続配置と分散配置の差。

CSVはExcelで読めるUTF-8 BOM付き。初成立ターンの空欄は未成立。
CIはseed変動の正規近似。各対比系列について78/72比較のBonferroni区間も保存。
共同作業対シャッフルは指標・A/B別に18比較を補正。全副指標の一括保証ではない。
多重比較の考え方は[NISTのBonferroni解説](https://www.itl.nist.gov/div898/handbook/prc/section4/prc473.htm)に従う。
今回の計算は同seed差の標準誤差に正規分布の係数を掛けた大標本近似であり、
NIST掲載のANOVA用t区間をそのまま実装したものではない。
差の分散が0なら区間幅も0になるが、観測外seedでも必ず同じという証明ではない。

## PowerShellで再実行する

まず移動する。

```powershell
Set-Location "<cloneしたリポジトリのフォルダ>"
```

少数seedで確認する。出力先を省くと新しい日時名フォルダになる。

```powershell
.\.venv\Scripts\python.exe -X utf8 -m poc.ab_poc.event_format_48_experiment --seed-start 101 --seed-end 102
```

全1000 seedを再実行する。

```powershell
.\.venv\Scripts\python.exe -X utf8 -m poc.ab_poc.event_format_48_experiment
```

表示された出力フォルダを指定して全件監査する。

```powershell
.\.venv\Scripts\python.exe -X utf8 validation/verify_event_formats.py "results/表示されたフォルダ名"
```

APIキー・有料LLMは使わない。既存UIに新しい設定画面は追加しておらず、
今回の13条件は上のコマンドから実行する。

## 失敗時・無効化

出力先の上書きは禁止。エラー時は末尾のエラーと最後のpair/seed進捗を確認。
manifest.jsonがなければ本体は未完了。complete.jsonはその既知ペアだけの完了。
自動再開・途中成果への追記は行わない。原因修正後に新しい出力先で再実行する。
監査失敗時は結果を確定扱いせず、ハッシュ・状態・CSVのどの照合かを切り分ける。

通常シミュレーションや24ターン版を使えば48ターンの介入は無効。
変更前の共通実験ファイルはvalidation/event-format-v1-before-48.pyに保管。
ローカルの維持管理はこのプロジェクトで行う。GitHubへの反映は未実施で、
別途の公開承認範囲。人間での効果やイベント滞在時間は今回の検証対象外。
